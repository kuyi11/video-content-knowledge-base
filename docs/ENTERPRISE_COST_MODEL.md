# 企业知识库 Token 与部署成本测算

本文用于售前演示，全部为假设参数和测算公式，不代表供应商报价或真实客户成本。

## 1. 测算维度

售前沟通时先确认三个维度：

| 维度 | 示例档位 | 需要确认 |
|---|---|---|
| 文档规模 | 1 万 / 10 万 / 100 万 chunk | chunk 平均长度、更新频率、Embedding 模型 |
| 访问规模 | 10 / 50 / 200 QPS | 峰值时段、并发查询、响应时间目标 |
| 部署模式 | API / 云上 / 私有化 | 数据敏感性、网络、GPU、运维责任 |

## 2. API 模式公式

设：

```text
Q = 每日问题数
I = 每个问题平均输入 Token
O = 每个问题平均输出 Token
W = 每月工作日
Pi = 输入每 1000 Token 单价
Po = 输出每 1000 Token 单价
E = 每月 Embedding、重排和其他调用成本
```

```text
月输入 Token = Q × I × W
月输出 Token = Q × O × W
月模型成本 = 月输入 Token ÷ 1000 × Pi + 月输出 Token ÷ 1000 × Po
月 API 总成本 = 月模型成本 + E
```

示例参数：每天 1000 次问答、平均输入 500 Token、平均输出 300 Token、每月 22 个工作日。将供应商的最新单价填入 `Pi` 和 `Po` 后即可得到 API 估算。

## 3. 云上和私有化 TCO

```text
云上月度成本 = API/模型成本
              + 应用计算
              + 向量数据库
              + 关系数据库
              + 对象存储
              + 日志与监控
              + 网络流量

私有化首年成本 = GPU/服务器一次性投入
                + 存储与备份
                + 部署实施人力
                + 首年运维人力
                + 模型和软件授权

私有化后续年度成本 = 运维人力 + 电力/机房 + 备份扩容 + 升级实施
```

## 4. 选型判断

| 情况 | 建议 | 主要原因 |
|---|---|---|
| 小规模验证、数据低敏感、访问量不稳定 | API | 上线快，初始投入低，适合 PoC |
| 中等规模、需要数据隔离、希望快速上线 | 云上或混合部署 | 兼顾弹性和控制力 |
| 高敏感数据、内网限制、稳定高并发 | 私有化 | 数据控制和性能可控，但硬件和运维成本更高 |
| 需要频繁更新知识库 | 增量索引 + 对象存储/数据库 | 降低全量重建和停机风险 |

## 5. 售前必须追问的问题

- 每天问题量和峰值 QPS 是多少？
- 平均问题长度和回答长度是多少？
- 文档总量、平均文档大小和更新频率是多少？
- 是否包含个人信息、合同、源代码或生产数据？
- 是否允许数据离开客户内网？
- 是否需要 SSO、组织架构和行级权限？
- 是否需要 GPU 常驻，还是可以接受按需调用？
- 目标响应时间、可用性和备份要求是什么？
- 谁负责模型、数据库、日志和索引升级？

## 6. Demo 中的表达方式

> 当前成本页使用假设参数和公开价格变量，目的是展示测算方法。实际报价需要结合客户的问题量、Token 分布、文档规模、峰值并发、数据敏感性、模型选择和运维边界重新核算。

## 7. 成本假设参数表

以下参数用于演示公式和收集客户输入，属于**假设参数，不是报价**。供应商单价留空，测算前应按选定供应商、模型、区域和计费周期填写经核实的价格。

| 参数 | 基准假设 | 单位/说明 | 价格或成本输入 |
|---|---:|---|---|
| 日均问题量 | 1,000 | 次/工作日 | 客户确认 |
| 工作日 | 22 | 天/月 | 按月估算，可替换为实际日历 |
| 平均输入 Token | 1,200 | Token/问题；包含问题、系统提示和检索上下文 | 以线上采样或压测校准 |
| 平均输出 Token | 300 | Token/问题 | 以线上采样或压测校准 |
| 大模型输入单价 | 待填 | 元/百万 Token | 按供应商、模型及区域价格表填写 |
| 大模型输出单价 | 待填 | 元/百万 Token | 按供应商、模型及区域价格表填写 |
| 每月 Embedding 文本量 | 6,000,000 | Token/月；假设每月新增/重建 10,000 个 chunk、平均 600 Token | Embedding 单价待填 |
| Embedding 调用量 | 10,000 | chunk 请求/月；实际批量接口可能合并请求 | 元/百万 Token 或供应商计费单位待填 |
| 重排调用量 | 22,000 | 次/月；假设每个工作日问题调用一次，候选 Top 20 | 元/千次或按部署资源测算 |
| 应用计算 | 2 vCPU / 4 GiB × 1 | 云 API 路径的起始配置假设，需压测校准 | 云实例单价待填 |
| 向量/关系数据服务 | 2 vCPU / 8 GiB × 1 | 起始配置假设；可合并部署时需评估可用性和容量 | 云实例单价待填 |
| 对象存储 | 100 GiB | 含原始资料和处理产物的容量预算 | 元/GiB·月待填 |
| 索引、备份与日志 | 50 GiB + 30 日 | 估算保留容量；日志保留受合规要求影响 | 存储与日志单价待填 |
| GPU 私有化方案 | 1 张 24 GiB 显存级 GPU | 仅作为私有化压测起点，不代表足够承载目标并发 | 设备折旧/租赁、电力和机房成本待填 |
| 运维投入 | 32 小时/月 | 假设 0.2 人月，用于模型、索引、监控、备份和故障响应 | 人时单价待填 |

### 计算公式

```text
月问题量 = 日均问题量 × 工作日
月输入 Token = 月问题量 × 平均输入 Token
月输出 Token = 月问题量 × 平均输出 Token
月生成成本 = 月输入 Token ÷ 1,000,000 × 输入单价
          + 月输出 Token ÷ 1,000,000 × 输出单价
月 Embedding 成本 = Embedding Token ÷ 1,000,000 × Embedding 单价
月重排成本 = 重排调用量 ÷ 1,000 × 每千次重排单价
月云上估算 = 月生成成本 + 月 Embedding 成本 + 月重排成本
            + 应用计算 + 数据服务 + 存储 + 日志监控 + 网络流量
私有化月度 TCO = GPU/服务器折旧或租赁 + 电力/机房
                + 存储备份 + 运维人力 + 模型授权
```

基准假设下月问题量为 22,000；月输入约 26.4M Token，月输出约 6.6M Token。此处只展示用量推导，不填入未核实的供应商单价，也不把 API、云资源和私有化硬件三种方案重复相加。峰值并发、缓存命中、重试、索引重建、GPU 利用率和可用性要求应在客户访谈与压测后另行调整。
